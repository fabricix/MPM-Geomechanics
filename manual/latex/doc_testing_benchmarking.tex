
\section{Testing Compilation and Benchmarking}
\label{sec:testing_manual_howto_compile}

In order to compile the testing and benchmarking executables, please follow the instructions below.

\subsection{How to Compile} 

	

Prior to proceeding with these instructions, please refer to \underline{\hyperref[sec:required_programs]{the list of required programs}}.

\par\medskip
The tests use \inlinecode{GoogleTest}. It is necessary to import this library by cloning the official repository. In the root directory of the project, execute the following command to clone the GoogleTest repository:

\begin{lstlisting}[language=bash]
	git clone https://github.com/google/googletest.git external/googletest
\end{lstlisting}

\par\medskip
The simplest way to compile on Windows and Linux is by using the \inlinecode{.bash} file at \inlinecode{/build/qa} with \inlinecode{MSYS2 MINGW64} console line, simply execute the following command in the directory \inlinecode{MPM-Geomechanics/build/qa}:

\begin{lstlisting}[language=bash]
	./cmake-build.bash
\end{lstlisting}

\par\medskip
Alternatively, you can use the following commands:

\begin{lstlisting}[language=bash]
	cmake -G "Unix Makefiles" -B build
	cmake --build build
\end{lstlisting}

\par\medskip
These commands will generate two executables: \inlinecode{MPM-Geomechanics-tests} and \inlinecode{MPM-Geomechanics-benchmark}.

\begin{itemize}
	\item \inlinecode{MPM-Geomechanics-tests}: Run testing using GoogleTest. All files ending with \inlinecode{.test.cpp} are testing files, you can find them in the directory \inlinecode{qa/tests}.
	\item \inlinecode{MPM-Geomechanics-benchmark}: Run benchmark using GoogleTest. All files ending with \inlinecode{.benchmark.cpp} are performance files. You can find them in the directory \inlinecode{qa/benchmark}.
\end{itemize}

\subsection {Running the Tests with MPM-Geomechanics-tests}

To run the tests, use the executable \inlinecode{MPM-Geomechanics-tests}. This executable will automatically detect all test files ending with \inlinecode{.test.cpp} in the \inlinecode{qa/tests} directory and execute them using GoogleTest.

Execute \inlinecode{MPM-Geomechanics-tests} at \inlinecode{build/qa}:
\begin{lstlisting}[language=bash]
	./MPM-Geomechanics-tests
\end{lstlisting}

The output will display the results of each test, indicating whether it passed or failed.

\subsection {Running the Benchmark with MPM-Geomechanics-benchmark}

To run the benchmark correctly, it uses a JSON file named \inlinecode{benchmark-configuration.json}. This file is located in \inlinecode{build/qa} directory and must be present there. 

This file allows the user to specify values for each test. If the file does not exist or a value is missing, a default value will be used.

\par\medskip
Execute \inlinecode{MPM-Geomechanics-benchmark} at \inlinecode{build/qa}:
\begin{lstlisting}[language=bash]
	./MPM-Geomechanics-benchmark
\end{lstlisting}

The executable allows the following command-line arguments:
\begin{itemize}
	\item \inlinecode{<directory>}: Specifies which file should be used to run the benchmark. If no file is specified, the program will use \inlinecode{benchmark-configuration.json} located in \inlinecode{build/qa}
\end{itemize}

\par\medskip
The executable allows the following command-line flags:
\begin{itemize}
	\item \inlinecode{--log}: Shows more information about missing keys in the \inlinecode{benchmark-configuration.json} file
\end{itemize}

\subsection {Alternative method for running benchmarks: \inlinecode{start-multi-benchmark.py}}

The performance test can also be executed using the \inlinecode{start-multi-benchmark.py} script, which allows running benchmarks with one or more executables downloaded as artifacts from GitHub and stores the log results in separate folders. Each executable is automatically downloaded from GitHub as an artifact, using an ID specified in \inlinecode{start-multi-benchmark-configuration.json}. Additionally, the benchmark configuration (number of martial points and number of threads) can be defined in the same file. 

Example of a \inlinecode{start-multi-benchmark-configuration.json} file:

\begin{lstlisting}[language=bash]
	{
		"executables": {
			"win_benchmark_executable": "./MPM-Geomechanics-benchmark.exe",  
			"win_github_id": "17847226555" 
		},
		"parameters": {
			"particles": [ 15000, 25000, 50000],  -> material point to test
			"threads": [1, 5, 10]  -> number of threads to test
		}
	}
\end{lstlisting}

In the example above, \inlinecode{win\_benchmark\_executable} specifies the path to the benchmark executable, and \inlinecode{win\_github\_id} provides the corresponding GitHub artifact ID. The parameter \inlinecode{particles} defines the number of material points to test, and \inlinecode{threads} specifies the number of threads to use for each test.

This setup will run 3x3 (particles x threads) totaling 18 tests (3x3x2). The executable \inlinecode{start-multi-benchmark.py} allows the following command-line flags:

\begin{itemize}
	\item \inlinecode{--clear}: Removes the \inlinecode{benchmark} folder (if it exists) before executing the performance tests. 
	\item \inlinecode{--cache}: Uses the previously created cache instead of the \inlinecode{start-multi-benchmark-configuration.json} file.
\end{itemize}
